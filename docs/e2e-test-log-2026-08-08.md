## Follow-up retest (same day, after user provided the real file-upload-service URL)

The user corrected `FILE_SERVICE_URL` to the real service: `https://fms.easydev.in`. Found and fixed a **second, independent bug**: `docker-compose.yml` hardcoded `http://host.docker.internal:5000` for the `api` and `ai` services (3 occurrences), silently overriding the correct value already present in `apps/api/.env`. The `worker` service was correctly configured and unaffected. Fixed all three, recreated `api`/`ai` containers, confirmed via `docker compose exec ... env` that both now show `FILE_SERVICE_URL=https://fms.easydev.in`.
